# Codex Interface セキュリティ設計（MVP）

最終更新: 2026-05-14

## 1. 脅威モデル（簡易）
- LAN内の他端末による不正アクセス
- トークン漏えいによるセッション乗っ取り
- 中間者攻撃（自己署名TLS時の検証不足）
- 過剰なコマンド実行によるDoS

## 2. 認証・認可
- 初期認証はローカルPIN
- PIN成功後に短期アクセストークン（JWT, 15分）発行
- リフレッシュトークンは長期（7日）だがデバイス紐付け
- `deviceId` 単位でトークン失効可能
- コマンド実行は `scope=exec` が必要

## 3. 通信保護
- 推奨: HTTPS/WSSのみ
- LAN MVPでは自己署名証明書を許容
- 初回接続で証明書フィンガープリントを表示し、ユーザー確認後に信頼保存（TOFU）

## 4. セッション保護
- 同一 `deviceId` で同時セッション数を制限（例: 2）
- 一定時間無操作で自動失効（例: 30分）
- 明示ログアウトでrefresh tokenをサーバ側無効化

## 5. 入力検証と実行制限
- 受け入れコマンドをallowlist化
- 引数スキーマ検証（JSON Schema）
- 実行時間上限（timeout）
- 同時実行数制限（例: 2）

## 6. 監査ログ
- 認証成功/失敗、コマンド実行、設定変更を記録
- 最低保持期間: 14日（MVP）
- ログは改ざん検知用にハッシュチェーン化（拡張）

## 7. レート制限
- `/auth/pin`: 1分あたり5回
- `/commands`: 1分あたり20回/device
- WebSocketは秒間メッセージ上限を設定

## 8. 運用ルール
- デフォルトPINの強制変更
- 定期トークン鍵ローテーション
- 依存パッケージ脆弱性スキャン（週次）
