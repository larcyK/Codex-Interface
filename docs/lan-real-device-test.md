# LAN 実機テスト手順

目的: スマホから同一LAN上のGatewayに接続し、認証・WS接続・コマンド実行・ログ確認までのフローを実機で検証・記録する。

前提
- 開発マシンとスマホが同一LAN (Wi‑Fi) に接続されていること
- Firewallでポート 8000, 8001 が開いていること（ローカルでのテスト時は問題ないことが多い）

準備（開発機）
1. 依存をインストール: `npm install`
2. Gateway を開発モードで起動（別ターミナル）:

```bash
npm run dev:gateway
```

3. Mobile PWA を開発モードで起動（別ターミナル）:

```bash
npm run dev:mobile
```

- もしくは PWA をビルドして `vite preview` 等で配信しても良い。

テスト手順（スマホ）
1. スマホのブラウザで `http://<開発機のIP>:5173`（Vite dev の場合）または `http://<開発機のIP>:<preview-port>` にアクセス。
2. `接続設定` セクションで `LAN上を発見` を押す。見つかったサーバ一覧が表示されるはず。
3. 見つかったサーバの `接続` を押して `API Host` と `WS URL` を設定。
4. `Health確認` を押して `状態` が `ok` などであることを確認。
5. `認証` セクションで Device Name を入力し、PIN を入力して `PINログイン` を実行。
   - 正常なら `Token` が表示され、`RefreshToken` が保存済になる。
6. `WS` の状態（`WS: ✓接続中`）を確認し、`WSイベント` に `server.status` 等のログが流れることを確認。
7. `セッション/コマンド` で `セッション開始` → `コマンド実行` を行い、結果が返り、`Logs` にも記録されることを確認。
8. `ログクリア` / `再接続` 等の操作を実施して挙動を確認する。

記録項目（検証時にメモ）
- スマホ機種・ブラウザ
- 開発機 IP
- 発見結果（discovered に表示された名前/IP）
- PIN ログインの応答（HTTP コード、body の内容）
- WS イベント（`WSイベント` 表示のスクリーンショットまたはログコピー）
- コマンド実行の結果
- 問題が発生した場合の再現手順

トラブルシュート
- ブラウザで `CORS` エラーが出たら、Gateway の CORS 設定を確認
- mDNS が見つからない場合は `.local` 名に対する解決がスマホ環境で可能か確認
- WS 接続がすぐ切れる場合は、PWA の `WSイベント` ログを確認して切断理由（code/reason）を貼ってください

終了処理
- Gateway と PWA を停止するには、起動したターミナルで Ctrl+C を押す
